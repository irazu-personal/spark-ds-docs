Button

Buttons trigger actions or navigate users through the interface. Spark provides multiple button types for different levels of visual emphasis.

Overview

The Button component supports multiple visual types (Primary, Secondary, Tertiary, Ghost, Link, Text), an icon-only sub-type, four sizes, and a Danger variant for destructive actions.

Usage Guidelines

For Designers

  • Use Primary for the single most important action on a page (e.g., "Save", "Submit")
  • Use Secondary for actions that complement the primary action
  • Use Tertiary for supporting actions that need less visual weight
  • Use Ghost for actions in toolbars, table rows, or tight spaces
  • Use Link for navigation-style actions within content
  • Use Text for inline actions with minimal visual footprint
  • Limit to one Primary button per view to maintain clear hierarchy
  • Use Danger only for destructive actions (delete, remove, cancel with data loss)
  • Choose size based on context: Tiny for dense UIs, Small for forms, Medium for general use, Large for hero sections
Do

Pair Primary with Secondary for clear hierarchy.

Don't

Avoid using two Primary buttons side by side.

Accessibility

Keyboard

Enter or Space activates the button. Tab moves focus in document order.

Focus Ring

A visible ring using --semantic-button-border-focus appears on keyboard focus (2px solid, 2px offset).

Screen Readers

Use native <button> elements. Icon-only buttons require aria-label. Disabled buttons use both disabled and aria-disabled="true".

Color Contrast

All text/background combinations meet WCAG 2.1 AA (4.5:1 for normal text, 3:1 for large text). Disabled states are exempt.
